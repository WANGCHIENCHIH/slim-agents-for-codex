# v0.4.4

## What's New

Selectively adopts Council checkpoint guidance from the reviewed oh-my-opencode-slim v2.2.21 release range. The upstream fix first shipped in v2.2.20 ([#1177](https://github.com/alvinunreal/oh-my-opencode-slim/pull/1177)). Preset IDs, role names, and model/effort mappings remain unchanged.

Adds `$slim-goal-loop` for a general Root task to coordinate Council advice and Orchestrator execution until acceptance is verified or a concrete blocker needs input. Supply a goal and acceptance criteria. Installation now includes three managed Skills; the workflow does not run under a restricted coordinator Root profile or wake a stopped host automatically.

## Fixes & Reliability

- Generated Council agents and the managed Council Skill follow the host's requested checkpoint or compaction-summary template. Normal Council synthesis retains the three-section report and existing advisory boundaries.
- Since the previous published release, v0.4.0, Orchestrator has gained explicit specialist lifecycle controls and reconciles artifacts and validation evidence before redispatching work, including when a specialist returns an empty reply.
- Installation accepts UTF-8 BOM configuration files while preserving their BOM and line endings. CLI commands work through linked installation paths, and CI smoke-tests the actual packed installation across Windows, Linux, and macOS.
- Regression coverage verifies both prompt entrypoints. Generated and packaged artifacts are checked; live Codex compaction behavior has not been verified.

## Installation / Upgrade

Download `slim-agents-for-codex-0.4.4.tgz` from this release, then run:

```bash
npm install --global ./slim-agents-for-codex-0.4.4.tgz
slim-agents-codex switch-preset --preset openai-5.6 --scope global
```

For a first installation, use `install` instead of `switch-preset`. Use `openai-5.5` to retain that model generation. Start a new Codex task after updating agents and Skills.
